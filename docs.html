Product Documentation Suite

Practical product management documents authored to define the vision, business justification, functional requirements, and technical architecture behind the Product Pipeline simulation game.

1. Business Case

Executive Summary

Onboarding junior Product Managers, Business Analysts, and delivery leads onto structured governance frameworks (RACI, BABOK, PMBOK, and Agile Scrum) typically relies on passive slide decks. This leads to role confusion during real projects and missed stage gates.

Objectives & Value

  • Faster Role Clarity: Help practitioners practise assigning Responsible (R), Accountable (A), Consulted (C), and Informed (I) roles across 10 standard delivery phases.
  • Zero-Cost Delivery: Build as a lightweight static web app requiring no backend servers, databases, or user accounts.
  • Portfolio Demonstration: Showcase end-to-end product thinking from initial concept through to live deployment.

2. Business Requirements Document (BRD)

Core Functional Requirements

  • FR-01 Sequential Stage Progression: Users must complete stages 1 to 10 in order. Locked future stages must display a clear warning if clicked early.
  • FR-02 RACI Validation Engine: Each phase must evaluate 7 stakeholder roles (Product, SLT, Sponsor, UX/CX, Dev, Legal, Risk) against an expected governance matrix.
  • FR-03 Deliverable Alignment: Users must match the correct framework artifact block to the active stage via drag-and-drop before unlocking the phase output.
  • FR-04 Artifact Preview & Sign-Off: Once RACI and framework checks pass, the system must unlock the stage's formatted deliverable document and allow advancement.
  • FR-05 Guided Onboarding Tour: First-time visitors must receive a step-by-step walkthrough modal, with an option to reopen it anytime from the header.

3. Business Analysis Summary (BABOK Aligned)

Target User Personas

  • Aspiring & Junior PMs: Seeking practical hands-on repetition to internalise governance ownership across discovery, build, and launch phases.
  • Hiring Managers & Recruiters: Reviewing the tool to evaluate structured product thinking, domain knowledge, and execution clarity.

Gap & Workflow Analysis

Traditional RACI spreadsheets show a static grid all at once, which overwhelms learners. Breaking the matrix into 10 isolated stage gates with contextual hints reduces cognitive load and reinforces why ownership shifts between Product, Engineering, Legal, and Sponsors at each milestone.

4. Technical Brief

Architecture Overview

  • Frontend Stack: Built with React and Vite for fast local development and lightweight static bundle generation.
  • Data-Driven Phase Engine: All 10 stages, RACI rules, hints, and artifact templates are decoupled into a single configuration object (metrics.js), making content updates possible without touching UI logic.
  • Client-Side State Persistence: Uses browser localStorage to save active stage, unlocked progress, and tour completion state with zero backend overhead.
  • Hosting: Deployed as static assets via GitHub Pages for high availability and zero ongoing hosting costs.
